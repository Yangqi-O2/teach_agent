## 一、先选一条阅读路径

不同目的不用读完全部文档。三条路径覆盖绝大多数场景：

| 你是 | 按这个顺序读 | 大约耗时 |
|---|---|---|
| **第一次接触这个项目** | 本文件 → [`../README.md`](../README.md)（看效果图）→ [`DESIGN.md`](DESIGN.md) §0–§1（产品构想） | 15 分钟 |
| **要改代码 / 加功能** | [`STATUS.md`](STATUS.md)（看清楚哪些已实现、代码在哪）→ [`FRAMEWORK.md`](FRAMEWORK.md)（能力协议、工具、迁移）→ 对应能力的契约文档 → [`CLEANUP.md`](CLEANUP.md)（安全与上线约束） | 40 分钟 |
| **要评审 / 演示 / 申报** | [`PROPOSAL.md`](PROPOSAL.md)（申报口径）→ [`DESIGN.md`](DESIGN.md) §0 一页速览 → 对应能力的验收清单 | 20 分钟 |

只想跑起来看效果？直接看 [`../README.md`](../README.md) 的「快速开始」，一条 `./scripts/start.sh` 即可。

## 三、有意留在 `docs/` 之外的三篇

整理时没有把所有 Markdown 都搬进来，是因为这三篇**放在原位才有作用**：

| 文件 | 实际路径 | 为什么不能移动 |
|---|---|---|
| **项目首页** | `README.md`（仓库根） | GitHub / Gitee 只把仓库根的 `README.md` 渲染成首页。挪走等于项目没有门面。 |
| **数据目录说明** | `data/README.md` | `data/*` 被 `.gitignore` 排除，这个文件是**让目录本身能进版本库的占位符**。删掉或移走，新克隆的仓库里不会有 `data/`，启动脚本会报错。 |
| **环境变量模板** | `apps/server/.env.example` | 是配置模板而非说明文档，必须与 `.env` 同目录才能被直接复制使用。 |

## 四、文档维护约定

避免再次出现「代码走了、文档停在原地」：

1. **改了能力的行为，同步它的契约文档。** 教材库 → `LIBRARY.md`，英语 → `ENGLISH.md`，简报 → `WECHAT-DIGEST.md`。
2. **改了能力协议/内核，同步 `FRAMEWORK.md`。**
3. **改了安全或部署相关，同步 `CLEANUP.md` 与 `DEPLOY.md`。** 两处都写了上线必做项，不能只改一处。
4. **验收类文档（`VERIFICATION-*`）不追着代码改。** 它们是「当时确实这样测过」的证据，正文已标注快照日期；结论变化时**新写一份**，而不是改写旧的。
5. **状态只有一个真源**：`docs/STATUS.md`。功能上线时改两处——`STATUS.md` 的表，
   以及 `app/capabilities/<name>/capability.py` 的 `status` 字段（前端徽章跟着它变）。
   其余文档不要再自己维护一份进度，只引用本表。
